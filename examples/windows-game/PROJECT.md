# Example: Lantern Trail project policy

Lantern Trail is a fictional single-player Windows puzzle game. All owners,
approvals, revisions, engine names, commands and results in this example are
synthetic. No engine, game or pipeline is supplied or executed by Temper.

The fictional owner has chosen Windows x64, C# and fictional Lumen Engine 1.0.
The exact real engine/toolchain would need a retained, verified lock record in a
real project. Multiplayer, account services, cloud saves and public telemetry are
outside this first increment. Product contracts cover puzzle progression,
controller/keyboard input, accessible menus and versioned local saves.

## Selected policy

The project adopts the [portable method](../../METHOD.md) at illustrative revision
`1111111111111111111111111111111111111111`; a real adoption replaces that synthetic
pin with verified retained provenance. No optional forge, agent/model or BSD
profile is selected. The project has no required policy service or parser.

The fictional owner explicitly adopts [policy.toml](policy.toml) as the sole
module selection/reference record: execution, verification and integration.
It identifies their canonical paths, owner identifier and prerequisites; the
rule prose remains in those documents. This metadata order grants no precedence
and needs no parser to read. The optional checker reports declared structure,
not whether the fictional permission is real or the game works.

These local module bytes are bound by the containing project revision. They have
no external policy dependency. Rule IDs identify obligations; wording lives in
its module. The game owner approves module selection/replacement and authority
changes through a reviewed decision. Current active exceptions: none. Historical
records do not grant current permission. Conflicts stop dependent work.

## Work and decisions

A local work tracker owns finite tasks, priority, ownership, acceptance, results
and continuation. It is independent of the chosen source host. The owner selects
product scope; agents can implement accepted tasks and choose routine details
within these contracts. An adopted method does not change them automatically.

Original project and asset licensing is chosen by the owner before distribution;
third-party assets retain recorded rights. The policy requires provenance for
art, audio, fonts and dependencies. It permits synthetic/local fixtures and no
player-data collection. No secret, paid service or account permission follows.
