# Offline verification

Run the same command locally and in CI:

```sh
python3 tools/verify.py
```

Use Python 3.11 or newer. The tools use only the standard library. They do not
install packages, access the network, or require Git. The command resolves the
repository from its own location, so it also works in a downloaded source archive.
Exit status 0 means the tests and document checks passed. Exit status 1 means at
least one check failed, or no tests were discovered. Diagnostics identify the
source file and line.

## Optional adoption auditor

Use the standalone [adoption auditor](../docs/how-to/audit-adoption.md) for an
explicit, read-only comparison of a consumer bundle and selected role files with
a trusted local source copy. It is optional and does not run as a consumer audit
from `verify.py`; the verifier runs only its synthetic fixture tests. It performs
no network, Git, subprocess or role execution and adds no integration authority.

## What the checker verifies

The checker reads UTF-8 files whose extension is `.md`, excluding `.git`, `.venv`,
and `__pycache__` directories. For each document, it checks:

- Exactly one ATX H1 heading, written with `#`.
- No trailing whitespace, including in code examples.
- Closed fences of at least three backticks or tildes.
- No unresolved template tokens outside `templates/`. Tokens use two opening
  braces, an uppercase name with underscores or digits, and two closing braces.
- Existing destinations for inline relative links and images, with exact filename
  and directory case on every platform.
- Existing heading fragments for links to Markdown files.
- No absolute local paths, unsupported URI schemes, or paths that resolve outside
  the repository, including symlink escapes.

Template tokens are permitted in `templates/`. A template link containing a token
is checked after substitution in the consuming project. Other template links must
resolve or appear in code examples.

## Markdown conventions

Use inline links and images on a single line. Enclose destinations containing
spaces in angle brackets, or percent-encode the spaces. Optional link titles and
balanced parentheses in destinations are supported. Relative parent paths are
allowed when they stay inside the repository. Directory links are allowed.

Use ATX headings. Common GitHub-style anchors are generated by lowercasing heading
text, removing punctuation and inline formatting, replacing spaces with hyphens,
and adding numeric suffixes for repeated headings. Unicode letters are preserved.
Prefer simple headings when links depend on their anchors.

Links and headings in fenced code or single-line inline code are ignored. Template
tokens and trailing whitespace are checked in code too. Reference link definitions
and explicit reference links are rejected; convert them to inline links.

HTTP, HTTPS, and mail links are not fetched. Root-relative website paths are rejected
because these documents must also work in a source checkout. Use full web URLs for
website destinations. Fragments are supported only for checked Markdown headings.

## Limits

This is a convention checker, not a complete Markdown parser. It does not validate
HTML links or anchors, setext headings, indented code blocks, multiline links or
code spans, nested link labels, shortcut reference syntax, or malformed Markdown
outside the checks above. Use the documented subset for repository documents.

A passing result does not establish factual accuracy, useful tests, policy
compliance, security, or ASD-STE100 compliance. Human and agent review must inspect
the content, evidence, and rendered result.
